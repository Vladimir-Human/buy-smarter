# CLI и кэш LLM

Назад в [README](../README.ru.md).

```bash
# LLM-парсинг запроса через библиотеку claude-cli (API-ключ не нужен)
buysmarter recommend "нужен ирригатор, портативный, IPX7, до 40000 тг, Алматы"

# Сохранённые настройки поиска, как «Настройки поиска» в приложении: город, бюджет, площадки, бренды
buysmarter prefs
buysmarter prefs set marketplaces kaspi,olx
buysmarter prefs set excluded_brands "Noname, Generic"
buysmarter prefs clear budget

# Вкус в одежде (экран «Стиль»; для фото нужен extra `style`)
buysmarter style
buysmarter style add ~/style/like                # фото или папки; --no — то, что не нравится
buysmarter style brands "Salomon, New Balance"   # ищутся на Kaspi для одежды
buysmarter style strength 30                     # вес оси «Стиль»; 0 — выкл., по умолчанию 20
buysmarter style never "белая глянцевая пластиковая подошва"   # LLM переводит один раз
buysmarter style remove 3f2a9c1d0e4b5a67.jpg
buysmarter style like https://kaspi.kz/shop/p/...   # фото найденного товара в образцы; dislike — в «нет»

# Сохранённые площадки (иначе все три) или выборочно; больше кандидатов; без md-отчёта
buysmarter recommend "ирригатор до 40000 тг" --sources kaspi,olx --top 10 --no-save

# Только проверенные бренды; без LLM (простой парсер, фичи не фильтруются)
buysmarter recommend "ирригатор" --city Алматы --budget 40000 --trusted-only --no-llm

# Знания о категории: сгенерировать (opus) или извлечь из своих заметок (sonnet)
buysmarter learn-category "робот-пылесос"
buysmarter learn-category "смартфон"      # тиры брендов и алиасы моделей для телефонов
buysmarter learn ~/notes/robot-vacuum.md --category "робот пылесос"

# Изученные категории, как экран «Категории» в приложении: список, итог, как оценивается категория
buysmarter category list
buysmarter category show "робот-пылесос"
buysmarter category set "робот-пылесос" used_market off   # composition, benchmark, official_stores
buysmarter category reset "робот-пылесос" used_market

# Смартфоны: индекс Kimovil в оси specs, «120 Гц» / «5000 мАч» как обязательные фичи
buysmarter recommend "смартфон до 250000 тг, 120 Гц, 5000 мАч" --city Алматы

# История цен: обойти отслеживаемые категории, недавние товары, затем один товар
buysmarter refresh
buysmarter history
buysmarter history "F300"

# Прошлые поиски, как в приложении: список, прочитать отчёт, повторить поиск
buysmarter reports
buysmarter reports show 1
buysmarter reports repeat 1
```

Вывод: лучший вариант со скором из 100, уверенность, раскладка по осям (бренд, цена с трендом за 30 дней,
отзывы, спеки, популярность, наличие с датой доставки), выжимка отзывов (плюсы, минусы, частые жалобы,
проверка требований), альтернативы, топ-N со ссылками и раздел б/у с OLX. Отчёты сохраняются в
`~/.local/share/buysmarter/reports/` (`--no-save` отключает), логи — в `~/.cache/buysmarter/logs/buysmarter.log`
(`BUYSMARTER_LOG_FILE` меняет путь). В папку, из которой вы запускаете, ничего не пишется.

Источники: **Kaspi** (JSON-эндпоинты), **Ozon.kz** (браузерная сессия Playwright), **OLX.kz** (открытый REST,
б/у). Аксессуары и нерелевантные объявления отсекаются эвристическим фильтром с LLM как запасным вариантом.
В разделе б/у дефекты, которые продавец сам называет в описании (трещины, «не включается», залит, слабый
аккумулятор, был в ремонте), выводятся в колонке Con, а объявления «на запчасти» отбрасываются.
Ранжирование также дисконтирует отзывы неизвестных брендов и штрафует подозрительно низкую цену.

**Понимание запроса.** До поиска запрос читается: что это за запрос. На неоднозначный вместо рейтинга приходит
вопрос: «подарок для мамы» — что именно искать, «iPhone 15 или S24» — с чего начать, «ремонт телефона» — это услуга,
«аыавыа» — переформулируйте. На терминале выбираете номер или пишете свой ответ; не больше двух раундов, потом
ищется первый вариант, и отчёт об этом говорит («Искал: …»). `--no-clarify` не спрашивает никогда. Товары с
ограничениями (алкоголь, табак и вейпы, оружие, с LLM — рецептурные лекарства) ищутся с предупреждением первой
строкой, без отказа. Бюджет читается по правилам, в которых единица измерения не становится деньгами: «до 50 штук» —
50 000 ₸, «до 2 м» и «4K» — не бюджет, «$500» — только пометка.

Коды выхода `recommend`: `0` — есть рекомендация (или объявления OLX, когда новое не подошло), `1` — рекомендовать
нечего (в том числе «искать нечего» после последнего раунда уточнения), `2` — ошибка запроса к площадке, `3` — нужен
ответ на уточнение, а stdin не терминал (вопрос напечатан).

## LLM: модели и кэш

Все LLM-вызовы идут через [claude-cli](https://github.com/octrow/claude-cli): через шлюз OmniRoute, если он
настроен, иначе через локальный `claude` CLI. У каждой задачи своя модель: дешёвая для парсинга запроса,
выжимки отзывов и запасных классификаций; sonnet для извлечения знаний из файлов; opus для генерации знаний
о категории. Каждая пара запрос/ответ кэшируется, повторный вызов бесплатный:

```bash
sqlite3 ~/.cache/buysmarter/llm_cache.db \
  "SELECT model, substr(cache_key,1,8), cost_usd, created_at FROM llm_cache ORDER BY created_at DESC LIMIT 10;"
grep "llm cache" ~/.cache/buysmarter/logs/buysmarter.log   # hit/miss каждого вызова
```
